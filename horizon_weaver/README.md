## Component responsibilities

| Component | Responsibility |
| --- | --- |
| Core messages and ports | Immutable, serializable contracts and typed interfaces |
| State IR | Versioned workspace, artifact, requirement, evidence and transition objects with validated relations |
| Runtime | Validate static dependencies and own resources with reverse cleanup |
| Harness | Read, write, run commands, capture snapshots and return execution facts |
| Evaluator | Run fixed contract checks and produce version-bound evidence and Verdict |
| Event Store | Atomically persist facts and checkpoints in SQLite |
| State Graph | Derive history, current state, pending actions and usage by replay |
| Context Compiler | Construct bounded input from contract, unmet checks, state and history |
| Policy and Model Gateway | Return Action, account usage and bound the model request |
| Transition Guard | Reject redundant reads only when complete current content was supplied; reject previously completed identical writes |
| Progress Monitor and Failure Reasoner | Measure changes, identify repetition and explain failures |
| Loop | Explicitly call component ports for one decision step |
| Supervisor | Own budgets, lifecycle, resume decisions and final termination |
| Reporter | Write the final result without changing decisions |

`composition.py` contains the static assembly mechanism. Business control uses explicit constructor injection and port methods, without a shared mutable RunState or a string event bus. SQLite events describe facts; they do not drive implicit callbacks.

## State representation and queries

`state_ir.py` defines the representation, `event_store.py` owns SQLite events, and `state_graph.py` projects recorded facts. `state.py` preserves the previous imports. Artifact identity includes path, content, kind, size and permissions. Workspace snapshots do not capture processes or network state.

`read_run(run_dir).ir` exports the representation. `read_run(run_dir).query` provides `parents`, `children`, `path_to`, `file_versions`, `touching`, `latest_observation`, `current_evidence` and `stale_evidence`. A recorded graph path does not replay commands or restore files. Self-check nodes retain policy provenance and cannot grant contract acceptance.

The default `context_strategy="state"` selects current required artifacts and recent relevant attempts, coalesces duplicate observations, and labels historical file versions. `context_strategy="recent"` preserves recent-history selection for development comparisons. Complete observations actually included in the input are recorded in `DecisionInput.visible_observation_steps`.

`transition_guard=True` uses those references before executing file actions. Truncated or omitted content, changed versions and failed reads remain readable. Shell commands and self-checks are not deduplicated. Guard rejections are logged as attempts with `tool_executed=False`, contribute no progress, and provide diagnostic feedback. Historical attempts without this field retain `None`, meaning execution provenance is unspecified by that older format.

The workspace is observed again after each decision. If it changed during the model call, READ may inspect the new version; other actions receive `state_changed_during_decision` when the guard is enabled. Commands and self-checks are never cached, but can be deferred by this version check. This covers observed file state, not complete filesystem transaction isolation.


## Task Contract and acceptance

Paths use workspace-relative POSIX syntax, including on Windows. `allowed_paths` lists existing workspace directories. File tools reject parent traversal and symlink escapes. Keep the run directory outside the workspace so logging cannot change task snapshots.

Checks are supplied by the human contract. Supported checks are:

- `text_equals`: exact UTF-8 text, including whitespace and newlines.
- `json_equals`: JSON structural equality with numeric equivalence; booleans are distinct from numbers. Duplicate keys and non-finite numbers are rejected.
- `command`: a human-defined assertion command whose successful exit indicates acceptance.
- `external`: an evaluator identity for a benchmark that runs hidden tests after the agent returns control. External checks cannot embed tests or be mixed with inline checks.

Command checks must leave the workspace unchanged. If any check changes tracked state, the evaluator rejects that evaluation. For example, configure test tools to avoid writing caches or generated reports in the task workspace. Python bytecode generation is disabled by the command harness.

The evaluator checks expected artifacts as well as the semantic checks. A command exit code of zero is an execution fact; only the evaluator can issue a passing Verdict. `verify` and `done` cannot attach, replace or weaken acceptance checks. After a write or command, acceptance runs again. The supervisor terminates successfully once all requirements pass on the recorded state.

With external checks, `done` terminates as `submitted`, with a non-passing Verdict. The benchmark's separate grading receipt establishes whether the candidate passed. `verify` cannot invoke hidden tests. `{"kind":"verify","command":"executable assertions"}` executes a policy-proposed self-check and records a separate `SelfCheckReceipt` in the attempt. Its command, tool result and workspace version are replayable facts; it never creates contract acceptance evidence. A check that modifies workspace files is rejected as proof.

Contracts can set `require_self_check=true`; the Terminal-Bench launcher exposes `--require-self-check`, defaulting to false in v1.2. When enabled, submission requires a passing check on the current workspace version and no failing current-state checks. Writes and permission changes invalidate older passes. This gate establishes that self-testing occurred; only the independent grader establishes correctness. With the gate disabled, a simple task can submit directly and verify observations still retain honest command results with unknown requirement coverage.

One decision may carry optional `notes` alongside its action. Public G/C references locate original goal lines and constraints; `evidence_steps` may cite previously executed reads, commands or checks. Legacy exact quotes and `check_steps` remain accepted. Invalid entries are ignored independently and valid siblings survive. Notes are policy coverage claims, stored in ModelCallCompleted and projected in State Graph / IR; they cannot change the contract or grant success. Context labels obsolete versions and evidence kinds separately. Empty requirements clear notes. No additional model call is needed. Print-only verify commands are recorded as observations when the submission gate is disabled; admitted checks retain unknown coverage and oracle independence.

Decisions default to 2048 output tokens and 60 seconds, bounded by task budgets. `Budget.output_tokens` is the hard output cap (8192 by default); `max_model_timeout_s` defaults to 120 seconds. Optional notes can request `next_output_tokens` / `next_timeout_s` for the next decision only, with clamping. A typed model timeout commits a no-action step and conservatively charges usage before continuing within remaining budgets. Other gateway errors stop the run. Truncated JSON never executes. Killing the local HTTP worker does not establish that remote inference stopped immediately.

Current small WRITE bodies are included under CURRENT WRITTEN SOURCE when their hash, length and file metadata match the snapshot. Full visibility is recorded in `visible_write_steps`; historical or clipped bodies cannot suppress a fresh read. Repeated failure summaries report commands, result identity, occurrence steps and the unchanged file state, without claiming that process/network state is unchanged. Commands always execute again when selected.

Command/verify actions may specify `timeout_s`, bounded by `Budget.max_tool_timeout_s` (120 seconds by default) and the remaining run budget; omission uses `tool_timeout_s` (30 seconds). The attached Docker adapter reserves one execution identity, persists its result outside the workspace, and supports status/output queries and cancellation of its own registered process group. Lost transport is reconciled using that identity without replaying the command. ToolResult records the identity and whether transport was recovered. Unknown outcomes still stop the run. Completed records are released when the adapter closes; EventStore keeps the final tool facts. The caller retains its container.

Snapshots include file contents, permissions, directories and symlink identities, excluding `.git`. Evidence currently binds to the whole snapshot, which conservatively invalidates all evidence when tracked state changes. This version does not restore arbitrary files or Git revisions.

## Persistence and recovery

Each run directory contains:

- `events.sqlite3`: versioned events with consecutive sequence numbers and a checksum chain. Full model input/output and tool output are retained here.
- `result.json`: a structured result with termination, usage, unmet requirements, snapshot, last checkpoint and pending steps.

The journal uses SQLite transactions and FULL synchronization. Execution facts, evidence and the checkpoint for a completed step commit together. Replay only deserializes facts and never calls a model or tool. Interrupted model requests retain a conservative token reservation.

```powershell
python -m horizon_weaver run --contract examples/v1/task.json --workspace examples/v1/workspace --run-dir runs/v1-model --backend docker --model YOUR_MODEL --base-url http://127.0.0.1:8080/v1 --resume
```

Resume requires the same contract, policy configuration, workspace, backend, code fingerprint and recorded execution environment. It preserves consumed budgets and committed steps, and reruns acceptance even when the workspace hash matches. If the workspace has changed externally, or an action/evaluation has an uncertain outcome, the run reports `recovery_blocked` instead of blindly repeating it. Reconcile the environment and use a new run for those cases. Completed runs are read through `inspect`; they cannot be resumed as fresh acceptance.

An abrupt crash can leave an external container requiring reconciliation. Internal event replay alone does not restore external process, temporary container storage or container state. Automatic continuation is verified for interruptions at committed checkpoints, with a matching workspace.

## Execution and budgets

The Docker backend mounts only the allowed workspace directories, disables networking, uses a read-only container root, drops capabilities and sets CPU, memory and process limits. With restricted directories, the remainder of `/workspace` is temporary container storage, without access to other host workspace files. Snapshots and file tools use the same allowed scopes. The local backend checks file paths but does not isolate arbitrary commands.

Windows command trees are started suspended, assigned to a Job Object and resumed. Timeout terminates the owned job; POSIX command trees use process groups. Docker commands also have an in-container process-group deadline and terminate remaining descendants after a normal exit. The model HTTP request runs in a separate cancellable worker, so a slow response cannot indefinitely extend its wait.

The supervisor enforces decision steps, model usage, consecutive no-progress steps and admission against remaining wall time. File scanning and final cleanup can add time beyond the admission deadline. Uncertain timed-out tool outcomes stop the run.

Context construction uses a conservative UTF-8 byte estimate plus framing allowance, rather than a model-specific tokenizer. Mandatory contract content is never silently truncated; if it cannot fit, the run terminates with `budget_exhausted`. Provider-reported usage is recorded when available; missing usage and failed requests are conservatively charged. Usage that exceeds the remaining budget prevents subsequent tool execution.

Failed acceptance receipts bound to the current snapshot take priority over old attempts. If initial or resumed acceptance has an uncertain execution outcome, the supervisor stops before requesting a model decision.

The active context reserves current file metadata before selecting history, presents selected attempts chronologically, and summarizes writes by path, size and content hash rather than repeating their bodies. Long tool outputs include explicit head/tail truncation markers; full records remain in the journal. Current policy-proposed self-checks have a separate label from independent acceptance failures. The gateway reads `finish_reason` so truncated action output receives actionable protocol feedback. HTTP workers use their runtime's package directory, preventing a different package in the caller's working directory from overriding it.

The newest tool observation gets the available context budget ahead of older output, up to 6000 UTF-8 bytes. Complete small source files are preserved when they fit; the async development trace exposed a 2024-byte source file whose critical central branch was lost by the previous fixed 1600-byte excerpt. Older observations remain compressed and omission markers remain explicit.

The model adapter accepts one strict action object or a typed `{"action": {...}, "reasoning": "..."}` decision envelope. Both validate against the same Action IR. Extra authority fields, multiple actions, conflicting envelopes and path escapes are rejected. Validation feedback contains concise field errors rather than echoing the malformed object back into context; the full raw response remains in the journal.

External grading is shown as pending, separately from unsatisfied inline requirements. Submission readiness is a pure projection of the recorded attempts and the current snapshot: `work`, `self_test_required`, or `ready_to_submit`. The final phase means runtime gates are satisfied; the original goal and independent grade still determine correctness. File edits invalidate readiness until a fresh check passes.

`NodeAgent`, CLI and TB now default to the direct `ir` frontend with `json_schema` decoding. The schema exposes only the capabilities enabled by the task and makes shell commands and structured checks mutually exclusive. Verification operands are constrained by check kind. Each request records capability flags and its decoder schema hash; runtime validation remains authoritative. File paths use relative POSIX syntax, and reasoning is limited to 300 characters. Providers must support JSON Schema; unsupported requests fail visibly. Use `--structured-output none` when deliberately testing unconstrained IR output.

The older `terminal` frontend remains selectable with `--policy-style terminal --structured-output none`. It lowers validated `act/tool/target` actions into the same IR. Its dev1 preflight exposed conflicting legacy command and structured-check instructions; that negative record is retained. Development comparisons use the same IR frontend and decoder across all four feature configurations.

Self-check preflight rejects recognizable observations such as standalone `cat`, `echo`, `true`, and inline Python that prints values without an explicit failure assertion. Rejected checks execute no tool and produce no self-check receipt; a subsequent actual test can satisfy the submission gate. The policy is instructed to calculate expected derived outputs from original inputs rather than copy the candidate as its oracle. This guard cannot prove arbitrary commands or delegated test scripts are adequate. Only the independent grader determines correctness.

The guard also recognizes counting/printing pipelines built entirely from known observation commands (for example grep counts piped to awk printing and echo). A pipeline that reports actual counts and a guessed expected count has no comparison and cannot satisfy the submission gate. Actual predicates such as `grep -q`, awk with an exit assertion, and unknown test programs remain executable; preflight is conservative and does not establish semantic coverage.

Container worker deadlines distinguish a confirmed execution termination from a lost transport. After killing and waiting for its managed process, a worker returns exit 124, `execution_terminated=true`, and `outcome_unknown=false`. The supervisor records failure, snapshots partial changes, and can continue repair. A Docker transport timeout or missing worker reply remains unknown and stops the run. Real Docker tests exercise a timed-out self-check followed by a write, a fresh passing check and submission, and verify that killed descendants make no late writes.
