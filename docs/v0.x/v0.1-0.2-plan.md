### 目标一句话描述
能否利用“结构化输入输出+图项目规划路径”，实现长时间10-20h稳定自主工作，同一项目对比IN tokens、OUT tokens根据API价格计算推理成本 < 10%，IN tokens、OUT tokens计算时间成本 < 1000% 即在同一数量级，而完成率 > 80%。

更简单一些，能不能通过输入输出内容的结构化以及精确的上下文管理，使得简单模型也能做出推理，完成简单科研探究闭环，从而显著降低长时间自主Agent工作的API成本。

**解释1.基础Agent能力测试集**：

**解释2.long horizon autonomous测试**：
给定研究项目自主探索，计算下列指标
探索效率：死节点支路 tokens / 全局 tokens

无人工干预有效工作时长：> 10h 如何定义有效工作？如何准确定义稳定/恢复？（探索效率 > 20% && 回环率 < 20% && |Best node - target node| < f(tokens) ）

**解释4.稳定自主工作的定义**
关于“稳定自主工作”的定义，不是不犯错，“即便是最为惊才绝艳的数学家，一生中提出的猜想也有80%是错误的”，科研就是不断犯错、不断修改最终得到结果的过程。关键在于“思路清晰的探索，并且将此前错误的探索经历转化为后续探索的经验，并继续向目标走去”，并不要求模型的能力来保证一次就中。就像slam那样，通过摸索对漆黑的房间“建图”并由此找到出路。

### 实现路径

**内容1.图导航**：
图由Agent自主搭建
图的形式：我希望是human readable的，这样人可以随时了解实验过程，参与Agent导航。本质上来说就是Prompt Engineering
图的结点：Agent探索过的状态
图的边：结点间的转移方式
System Prompt确保Agent在执行下一步前，确保当前结点+状态转移后的结点是没有探索过的

**结点信息**：
index: 项目关注的指标（客观）
changes：当前结点采取的变化（客观）和结点转移直接相关
inference：模型推理的：采取的变化->指标变化 这个映射关系（主管）

图直接使用git


**内容2.知识经验累积**：
建立自己的知识库，并纳入推理上下文
例如：需要将《科研错题本》与《科研注意事项》放到Agent中，避免出现重复犯相同错误。

全局知识经验：全局适用的知识，用户个性化

项目知识经验：项目图内的导航与planning，图导航的一部分


**内容3.最小实现原则**：
everything is structural，presented by IR
输入：所有文件组成文件树，即能快速了解全局信息，当前定位，也能找到当前详细信息
输出：
图规划中的结点，是项目过程的抽象，每一步的推理只有128k的上下文，也就是单次推理所有上下文和输出内容加起来 < 128k tokens
输出也是各个部分分别实现

最小实现、模拟器、数学模型、全局建模 -> 简单的，轻量的（结点转移planning）
具体实现 -> 各个部分分别实现（结点转移具体实现）

使用json文件格式

**内容4.轻量化用户渲染**
json是LLM处理的格式，写轻量化的渲染程序将内容呈现给用户
