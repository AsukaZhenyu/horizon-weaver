# HorizonWeaver v0.3 计划：Node Agent 基础设施

- 日期：2026-08-29
- 版本：v0.3（分层：科研探索层 / 问题解决层；引擎自动推断的上下文组织）
- 状态：**计划**（待实现）

---

## Context（为什么做这个）

v0.2 把科研探索层（图导航协议、结点三分、科研原则 10 条、精确上下文管理）整套压在了「解决 Terminal-Bench 任务」的执行器上。8 个冒烟任务本质都是「修好 pip / 处理 csv / 写对脚本」的小问题，根本用不到图导航；而 9B 模型被科研哲学分散注意力——读不懂错误、在琐碎命令里打转、诊断不到根因（冒烟 1/8，唯一通过的 pandas-etl 走的是「读数据→绕开缺依赖→verify」的纯执行路径）。

v0.3 重新分层：

| 层 | 职责 | 状态 |
|---|---|---|
| 高层（科研探索） | 结点 + 图导航：往哪探索、哪些已证伪、best 在哪，需要项目整体知识 | 未来实现（`loop.py` 是雏形） |
| 低层（问题解决）**Node Agent** | 给定已圈定的小任务，把它做出来，无科研/项目知识 | **v0.3 本次实现** |

Node Agent 作为**基础设施**，被高层 agent 与 `tb_test`（现 `keyan_agent` 改名）共同调用。

**核心新机制**：上下文 = 所有尝试的 `(action, result, inference)` 三元组；其中 `inference`（这一步意味着什么、下一步往哪走）由**引擎自动生成**（尤其对失败尝试），不让弱模型自己反思。

## 文件变更

### 1. `agent/node_agent.py`（新增，核心，~400 行）

- `Attempt` 数据类（放 schema.py）：`step / action_summary / target / exit_code / result / inference / verified`。

- `NodeAgent` 类：
  - `__init__(model_name="qwen3.5-9b", api_base=..., temperature=0.2, max_steps=100)`。

  - 保留 v0.2 常量 `STUCK_LIMIT=8`、`MIN_STEPS_BEFORE_DONE=2`，三张去重表 `seen_commands/seen_writes/seen_verifies`。

## 关键设计

### 引擎自动推断 `_summarize_attempt`（确定性，不做推理）

按 tool 分派 + 退出码分类 + 错误行抽取：

- bash/verify：`0`→「成功」；`127`→「命令未找到(127)」；`None`→「无退出码（可能超时/截断）」；其他→「失败({ec}) {错误行}」。
- write：成功→「已写入」；失败→「写失败: {output}」。
- read：→「已读（退出码 {ec}）」。

`_extract_error_line(output)`：优先取含 `Error|error|Traceback|No module|not found|No such` 的行，否则取最后非空行，截断 ~200 字符。

### 上下文组织 `_build_context`

```
## 目标
{instruction}

## 已尝试（动作 → 结果 → 推断）
1. write /app/x.py → 已写入 → 脚本就绪
2. bash pip install pandas → 失败(127) 未找到 pip → pip 缺失，试 python -m pip
...

## 下一步：输出一个动作 JSON
```

- **所有** attempt 都进（每条一行：action → result → inference）；`result` 截断 ~200 字符、错误优先（模型仍可用 `read` 工具取完整内容）。
- 总条数超预算时，最旧压缩为 `…(前 N 步省略)…`。
- 首步（无 attempts）时展示「## 当前终端」初始屏。

### 会话抽象

NodeAgent 依赖 duck-typed session（与 tools.py 一致）：`send_keys / get_incremental_output / copy_to_container / get_asciinema_timestamp`。tb_test 直接传 `TmuxSession`；未来高层 agent 传别的 session。
