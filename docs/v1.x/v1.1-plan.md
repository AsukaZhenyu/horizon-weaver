# HorizonWeaver v1.1 状态表示与组件协作设计

日期：2026-10-04。状态：首个状态闭环已实现，开发版本 `1.1.0.dev1`；八项真实模型 Terminal-Bench 开发冒烟为 2/8，完整记录见本文末尾。后续基础可靠性设计见 [v1.2-plan.md](v1.2-plan.md)。v1.0 尚未通过发布验收，不冻结版本或正式基线。

v1.1 将原先分散在领域消息和运行记录中的状态，整理成可序列化的 State IR，提供可查询的 State Graph，并通过 EventStore 保留原始事件。首个实现闭环让这些状态关系用于上下文选择和重复动作处理。这里的状态表示覆盖单个 Node Agent 的运行；完整的代码语义图、任务分解和长期记忆仍需要后续设计。

## 设计来源与选择

| 设计 | 来源 | 选择理由与替代方案 | 本版验证 |
| --- | --- | --- | --- |
| 结构化表示、组件化、上下文编排、客观验证 | 用户 README 的基础设计与本次对话 | 将用户方向具体化为可运行协议；实现不等于证明 structured IR 或 hierarchical refinement 假设 | 组件协作场景和状态查询 |
| State IR 的类型、身份、版本和关系 | 实现者补充，本次用户明确纳入 v1.1 | 明确组件交换的信息；可替代方案是自由字典，但难以验证关系一致性 | 序列化、引用与关系检查 |
| EventStore 保存事件，State Graph 从事件派生 | 实现者补充的持久化选择 | 保留执行出处并支持重放；快照存储也是可选方案 | 原子提交、损坏拒绝、无副作用重放 |
| 依据状态关系选择上下文 | 用户上下文管理目标的具体实现假设 | 优先当前版本和未满足要求，合并重复观察；保留 recent 配置用于开发对照 | 历史噪声场景，关键观察保留与输入字节量 |

这些选择使用类型化协议、依赖注入和事件重放等工程方法。尚未建立与特定论文或 Cordis 原文的逐项映射，不将它们宣称为外部框架要求或已验证的研究贡献。

## 三个模块的边界

### State IR

`state_ir.py` 定义不可变领域表示。对象身份与版本分离：同一路径可以有多个 Artifact 版本；相同工作区快照共用 State 节点；不同动作和检查拥有各自记录。文件快照覆盖内容、大小、类型和权限，不代表进程、网络或完整操作系统状态。

IR 包含运行 ID、任务合同、工作区状态节点、文件版本节点、验收要求、证据、自检记录、动作转移和运行控制信息。关系包括状态包含文件版本、转移的起点与终点、转移改变或观察文件、要求对应证据，以及证据所属的状态。验收证据与模型自检保持不同类型和权威来源。当前验收结论仍由 Evaluator 产生，IR 只能保留或作废已有结论。

ID 由内容或执行步数确定；序列化必须可重复。关系端点必须存在，端点类型必须符合关系语义。未知快照只允许作为历史证据所引用的占位状态，不能作为当前可执行状态。IR 同时保留历史与当前版本，供查询区分。

### State Graph

`state_graph.py` 从事件派生 State IR，并提供父子状态、路径、文件版本、相关动作、当前及过期证据查询。重放不调用模型、工具或 Evaluator。工作区状态可以回环，首次实现保留转移记录；路径查询表达图中已发生的转移，不表示可以自动重放副作用。

Context Compiler 通过查询按当前状态选择本轮工作集。相关性依据明确关系、当前文件版本、未满足要求、近期变化与失败；暂不推断 shell 命令的完整读写依赖。重复 READ 合并，旧版本 READ 的正文不作为当前源码展示。原始记录保留在事件中。模型需要当前完整内容时，运行时不得以历史截断观察阻止重新读取。

### EventStore

`event_store.py` 保存既有 RunEvent，保留 SQLite 事务、序号、版本和校验链。State IR 和查询索引均可从事件重建，不另设可修改的事实库。v1.0 的事件格式继续可读；`state.py` 保留旧导入入口。历史运行只能读取，恢复仍要求相同代码、合同、环境及已确认状态。

## 组件如何协作

| 组件 | 输入 | 输出与责任 |
| --- | --- | --- |
| Context Compiler | 合同、图视图、当前快照、预算 | 查询并选择上下文，记录完整展示过的观察引用 |
| Policy 与 Model Gateway | 本轮输入 | 一个 Action、原始响应和用量；不修改 IR |
| Transition Guard | Action、决策状态版本、当前状态、已展示观察 | 对可确认冗余的 READ 或 WRITE 提供执行前反馈；决策期间状态变化时阻止过期修改；可以关闭 |
| Harness | 通过执行前检查的 Action | 执行结果与快照；负责外部副作用 |
| Evaluator | 合同及当前环境 | 与当前版本绑定的 Evidence、Verdict |
| Progress Monitor | 前后状态、结果和历史 | 信息、状态、验证进展或无进展 |
| Failure Reasoner | 执行结果与验收状态 | 诊断反馈，不改验收标准 |
| Loop 与 Supervisor | 以上对象 | 调用组件，提交执行记录、证据和检查点，派生下一轮状态 |

流程是：读取状态 → 查询工作集 → Policy 提出动作 → 先记录提议 → 检查及执行 → 验收与进展评估 → 原子提交 → 派生新状态。执行前拒绝也是一次有出处的尝试记录，不制造执行成功。不能确认工具结果时继续遵守原来的恢复阻断规则。

模型响应后、执行前再次观察工作区，提议绑定此时的快照。若与本轮输入的状态版本不同，READ 可以观察新版本，其余动作在开启 guard 时返回 `state_changed_during_decision`，下一轮根据新状态重新决策。该检查保护可观察的文件状态，不宣称具有完整文件系统事务隔离。`Attempt.tool_executed` 区分实际执行、执行前拒绝与旧格式未指定执行出处。

## 范围和配置

本版实现独立三个模块、查询 API、状态上下文策略、重复动作处理和 CLI 状态导出。`context_strategy=state|recent` 与 `transition_guard` 是独立配置，保存到运行元数据，供开发对照；它们不改变模型前端或隐藏评分权限。

按文件依赖复用检查、AST 代码关系、子任务 DAG、并行调度、持久 shell、模型生成的语义压缩和缓存预取不在本次首个闭环内。任意命令和自检不缓存，不根据文件指纹推断进程或网络状态不变。

## 实现顺序和验收

1. 定义 State IR 与关系验证，分离 EventStore 和 State Graph，保留旧入口。
2. 实现版本、转移、证据和路径查询，提供 CLI IR 导出。
3. 将图查询接入 Context Compiler，验证旧关键观察能穿过长历史噪声，旧版本源码不冒充当前源码。
4. 接入 Transition Guard，验证完整观察已展示时减少重复读取，截断或版本变化时允许读取；等价写入有明确反馈。
5. 跑既有回归、新增状态场景与可重现开发对照；记录代码指纹、配置和负结果。

功能检查与开发对照可以在实现期间开展，不以冻结为前提。发布验收还需要真实模型和真实任务验证。验证指标分别记录状态一致性、关键事实保留、输入字节上界、真实工具调用次数，以及真实模型任务通过、正常收尾、token 和耗时；确定性场景不替代真实模型成绩。
