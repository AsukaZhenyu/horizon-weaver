# Horizon-Weaver v1.2：基础任务可靠性

日期：2026-10-04。基于 v1.1 的真实模型八项开发冒烟（2/8），先修复基础执行与信息传递，再测量准确率。本文不是版本冻结或性能提升声明。

## 目标与模块映射

保留现有单 Policy 决策、单动作执行、状态投影、独立验收的合作关系。没有新增业务模块、额外规划者或审查模型。模型决定解题方法；运行时保证收到真实、可追溯的信息。

| 改进 | 现有模块 | v1.2 行为 |
| --- | --- | --- |
| 1. 协议反馈 | TerminalPolicy / ModelPolicy / Core | 保留字段位置与错误原因；明确区分 JSON 截断、未知字段、路径错误、多个动作。兼容已有无歧义别名，不猜测多个动作的执行顺序；拒绝重复 JSON 键与非有限数值。 |
| 2. 工具执行 | Harness / AttachedDockerHarness / worker / Loop | command、verify 可请求等待时间，受单工具上限和剩余运行预算限制；默认等待 30 秒，上限 120 秒。附加容器命令有唯一执行 ID、可查询的状态和取消标记、持久结果；传输失败后只查询或取消原命令，不重放。超时已终止与结果未知分别记录。 |
| 3. 保留有用上下文 | ContextCompiler / StateQuery / TransitionGuard | 保留当前版本的近期小文件 WRITE 内容，减少写完立即重读；保留实际失败输出。源内容必须与当前文件哈希、长度和元数据匹配。历史版本标为过期，大内容继续按预算裁剪；仅完整可见内容可支持重复读取反馈。 |
| 4. 公共需求便签与自检 | Core / Policy / StateGraph / State IR / ContextCompiler / Evaluator | 一次决策可附带可选 notes，引用原始目标或约束的原文及已有检查步骤；这是 Policy 的覆盖主张，不能修改合同或产生验收成功。便签带状态版本，检查证据单独判断是否仍有效。自检显示“命令结果”和“需求覆盖未知”。TB 的强制 verify 门槛改为显式选项，默认关闭；模型仍被提示测试相关行为，可直接完成简单任务。 |
| 5. 重复失败反馈 | ProgressMonitor / FailureReasoner / StateQuery / ContextCompiler | 汇总同一命令、相同失败、同一文件状态的次数和步骤，展示原始错误，提示选择不同假设或诊断。记录的是文件状态相同，不能推断进程/网络也相同；不缓存或禁止任意 shell 重试。 |

## 协作与数据

Policy 的可选决策封装为 `{"action": {...}, "notes": {"requirements": [{"quote": "原始需求中的原文", "check_steps": [3]}]}}`。terminal 工具协议也可在同一对象附带 notes，列表形式 `notes:[...]` 是无歧义别名。省略 notes 保持旧协议；空 requirements 可清空便签。最多 12 条，每条原文最多 400 字，每条最多 8 个检查引用。便签格式错误、无效原文或不存在的检查引用都仅被忽略并反馈，已合法的动作仍然执行。运行时不替模型拆解自然语言要求。

ModelCallCompleted 保存有效便签；StateGraph / State IR 纯投影还原其来源、步骤和状态。ContextCompiler 始终保留原始合同，并把便签作为较低优先级辅助内容。只把真实已执行、仍在当前文件状态的检查列为可用证据；即使它退出 0，覆盖关系也是 Policy 主张。

Action 的可选 `timeout_s` 只用于 command / verify。Loop 记录实际执行等待上限，并为附加容器的终止确认保留少量预算。AttachedDockerHarness 在容器工作区外使用私有临时目录维护自己发起的命令状态；取消仅作用于已登记的进程组，并核对进程身份。命令输出落文件，避免后台进程持有管道导致回收阻塞。结束时清理自己创建的执行记录，保留调用者容器。无法确认结果时仍安全停止，不伪造已终止。

重复失败汇总由事实推导，不增加模型调用。source body、失败输出、文件清单、便签均计入同一上下文预算。EventStore 仍是不可变事件权威；增加带默认值的字段，旧 v1.1 账本仍可离线读取，旧运行不允许用新代码静默继续。IR 输出使用 1.2，同时接受旧 1.1 序列化表示。

## 验收

1. 协议：未知字段有具体修复反馈；多个动作、重复键、逃逸路径不执行。
2. 工具：真实 Docker 中确认超时终止、查询输出、取消、传输中断后的原命令结果恢复；相同命令不会因状态查询而重复执行。
3. 上下文：小 WRITE 无需重读即可得到完整当前源代码；过期或裁剪内容不能触发读取缓存反馈；预算上界正确。
4. 便签：随同一次模型决策保存和重放；伪造原文、检查步骤或成功不能升级验收；检查过期显示清楚；默认与强制自检配置分别覆盖。
5. 重复失败：相同输入和结果准确计数；状态改变后重新分组；重试命令仍执行。
6. 回归：现有测试与真实 Docker 测试；同模型、同八个原始 TB 任务、单次尝试，独立隐藏评分。保留所有失败、轨迹、源码指纹和配置，与 v1.1 开发冒烟比较。自检门槛与工具等待策略的改变单独披露，不能把自检成功率当成任务准确率。

## 后续修正：决策、需求引用与证据（1.2.0.dev2）

针对上述八项轨迹继续修正现有模块。保留单 Policy、单动作和独立验收；模型选择搜索策略，运行时提供预算与事实，不加入任务专用解题流程。

| 修改 | 现有组件 | 行为与边界 |
| --- | --- | --- |
| 单次决策预算 | Budget / ContextCompiler / ModelGateway / Loop | 默认每次输出 2048 tokens、等待 60 秒，与任务总时间和 8192-token 输出硬上限分开；等待硬上限默认 120 秒。仍受总预算约束。已完整决策可在 notes 请求下一步更大预算，超限裁剪，只使用一次，不增加规划调用。数值是实验起点。 |
| 模型调用超时恢复 | ModelGateway / worker / Loop / EventStore | 类型化可重试超时，保守计费、保存无动作决策与 checkpoint；没有提出或执行工具，允许下一轮继续。认证、协议、普通网络错误仍停止。总时间、步数、tokens、无进展上限仍生效。截断 JSON 不执行，不从不完整对象提取动作。取消本地 HTTP worker 不声称远端推理立即停止。 |
| 公共引用与逐条校验 | Core / Policy / StateGraph / State IR / ContextCompiler | G 编号是原始 goal 的物理行号，C 编号是约束序号；只添加定位，不解释语义或修改合同。便签可引用 ref、尚未确认的条件 uncertainty 与已有 evidence_steps；兼容旧 quote/check_steps。结构和语义逐条校验，有效项保留，无效项不阻断动作。明确的空 requirements 清空便签。 |
| 证据分类 | Loop / SelfCheckReceipt / ContextCompiler / FailureReasoner | 默认关闭提交门槛时，只打印的 verify 可以执行，但标为 observation，不构成 passing self-check；退出码仍如实记录。未被语法预检识别的命令为 check_candidate，覆盖和独立 oracle 仍未知，不能产生验收成功。读取、写入、命令与检查引用分别显示来源、执行结果和文件版本。 |
| 修复事实与失败优先级 | TransitionGuard / ContextCompiler / ProgressMonitor / FailureReasoner | 相同写入明确报告实际内容改动为零、未执行写入；当前文件状态上的最近真实命令失败在历史前展示，保留命令和错误。模型自行决定下一步诊断或修改。文件快照不覆盖进程、网络和外部状态。 |

协议示例：`{"action":{"kind":"read","path":"source.py"},"notes":{"requirements":[{"ref":"G3","evidence_steps":[2],"uncertainty":"尚未核对边界输入"}],"next_output_tokens":4096,"next_timeout_s":120}}`。引用只能指向先前真实执行的步骤；被 Guard 拦截的动作不能伪造新观察。预算请求对下一步生效，即使便签之后保留也不持续扩大后续调用。无需便签的简单任务仍能直接行动、提交。

验收先检查超时之后执行下一动作、tokens 计费与无进展终止；再检查混合有效/无效便签、读取证据不能授予成功、观察分类与过期证据、零改动保留错误。真实模型先做针对性预检，再在同一源码下重跑八项，每项单次尝试，所有失败保留。预检与完整队列分别报告，预算和提示变化单独披露。

### dev2 实现与真实模型结果

上述修正已实现，**131/131 回归通过，包含 12 项真实 Docker，无跳过**。八项旧事件账本仍可读取；八项初始工作区与 dev1 完全一致，源码、归档与所有 trial 的指纹一致：`3bea63019a7b74b9e513ff87fd0ebadd31b0fe2676d45b247b957d1d651558e7`。任务、评分和既有兼容文件未改，来源哈希与执行记录保留。

三项预检 **0/3、14/21**；完整八项 **3/8、20/30**，dev1 为 **3/8、24/30**。通过项仍为 hello-world、权限、日志汇总。异步任务从 5/6 退到 1/6；模型生成代码没有等待任务完成，只检查了导入。JQ 仍漏掉公开参数格式；Regex 虽恢复执行仍耗尽总预算；SQLite 重复不适用查询且恢复结果错误；Profiling 的依赖安装两次确认超时后，未重新通过自检即提交。

真实机制效果：完整队列有 **10 次有效便签决策**（dev1 为 0）；Regex 的 **2 次单次模型超时**后仍有后续实际动作。另有 1 次输出截断、3 次零改动写入拦截、4 次观察类 verify。未知工具结果和运行时误报成功均为 0。这些事实说明接口与恢复路径可用，不能证明便签或短决策预算提高准确率。

总 Agent 时间约 **932.2 秒**，dev1 为 985.8 秒，约下降 5.4%；其中有错误实现提前提交和失败任务提前结束，检查级正确率下降，不能声称整体性能提升。hello-world 本轮两步、17.9 秒；日志汇总从 7 步、65.1 秒变为 12 步、113.5 秒。单次采样、预检预热、同时改变提示和预算，不足以认定更好的默认策略。

**准确率优化尚未通过验收。** 2048-token / 60-second 是可配置的实验起点。后续仍需改善 Policy 对行为条件的检查、失败后的策略调整和提交判断，并分开测量预算与提示的影响。完整报告与预检负面记录见 `runs/v1.2-decisions-20261004/report.md` 和 `targeted-report.md`。
