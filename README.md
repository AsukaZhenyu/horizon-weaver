# Horizon Weaver v1.x

在 v0 之后重新设计的模块化终端 Agent，尝试以显式状态、执行记录和客观验证改善任务完成率。该系列已停止维护，保留源码、测试、设计文档和原实验报告。

## 开发过程

| 阶段 | 主要改动 |
| --- | --- |
| v1.0 | 拆分执行、策略、上下文、验证与生命周期管理 |
| v1.1 | 引入 State IR、State Graph 和 EventStore，记录状态与事件关系 |
| v1.2 | 改进动作协议、工具等待、自检与收尾 |
| v1.3 | 多轮调整探索历史、上下文组织、目标反馈和 Verify |

## 实验结果

主要使用 Qwen3.5-9B Q4_K_M、16k 上下文，每任务 40 步、300 秒，串行运行选定八项 Terminal-Bench 开发任务。

v1.1 为 **2/8**，v1.2 为 **3/8**；v1.3 多轮为 **2～4/8**。最终 dev19 为 **3/8 整项通过、2/8 正常提交且通过、11/30 检查通过**。当轮已有 302/302 回归测试通过，仍未验证稳定的任务收益。[最终报告](runs/v1.3-goal-contract-r21-20261012/report.md)

## 局限性

- 历史和目标记录更完整，不代表模型会据此改变策略，重复动作仍然存在。
- 证据存在、格式正确、自检通过，都不能证明任务需求已完整满足；加强检查还可能拖延提交。
- 组件与协作策略主要由人工设计，尚无根据执行反馈持续学习、积累和复用能力的闭环。
- 八项任务被反复用于开发，各轮多为单次采样，不能当作未知测试集或稳定的因果结论。

设计文档见 [docs/v1.x](docs/v1.x/)。源码在 `horizon_weaver/`，测试在 `tests/`，依赖见 `requirements-v1.txt`。完整对照与教训见[实验汇总](https://github.com/AsukaZhenyu/horizon-weaver/blob/codex/learnable-runtime/history/legacy-experiments.md)。
