# HorizonWeaver: Structured Context Orchestration for Long-Horizon Small-Model Agents

## Motivation

长期来看，理想情况下人每天只能专注工作7-8h，长期过长时间集中精力工作对人的心理与身体健康有害，并且会降低效率，就我实际体验来看，一天如果在工位上坐10h以上，能有2-3h的高效思考与工作就非常不错了。长期10h以上工作时长+交付物压力会导致：人的身体素质下滑，人疲惫焦虑，丧失与人交流的基本能力，人被“异化”了。

在工作中存在大量，可被自动化的，机械的工作。如果人的精力被这样的事物占据，则会导致疲劳以及效率低下，更可怕的是会失去对于人生、项目全局的把控，容易迷失在死胡同里。

例如：沉迷在具体的代码实现里，而忽略了项目的顶层设计，导致项目没有学术性/创新性，仅仅在工程上有意义，而随着AI的发展，这样的工作越来越没有意义，人也越来越没有价值。

又例如：硕士期间仅专注于当前交付项目的工作，没有形成独立完成科研闭环的能力，没有在一个领域内深度积累，毕业后只能作为耗材随波逐流找工作，这辈子将与自我实现无关，一切的梦想都化为泡影。

基本原则是：
做一个长期主义者，日拱一卒，个人的身心健康是最有价值的投资，8h睡眠、8h工作，另外8h要运动、兴趣以及与人交往。如果是8h睡眠、16h工作，等待着我的就是：30岁胃癌晚期还在工位上，养育着和我没有血缘关系的孩子，看着闪烁的屏幕直到失去意识，老婆分走所有财产，老爸老妈在农村靠着200块一个月的养老金过活。

我 8h / 3-4h 的工作需要发挥最大效益，目前的规划是：上午3h主要交付物工作，处理昨天Agent的实验信息，下午4h用于个人能力积累，晚上运动以及兴趣，目标是：从中午开始，Agent自动帮我处理主要交付物相关工作，例如：

1. PPT制作与美化
人：把控每页的内容，叙事逻辑
Agent：美化排版

2. 实验
人：制定抽象，搭建框架
Agent：自动debug，自动操作运行实验、探索参数，在框架内自主探索架构，整理文档、数据

> Agent就处理代码就行了，哪怕是硬件也可以用Verilog自行编译测试，确认功能和逻辑正确后，再人工烧录验证。就还是不处理多模态、自行操作电脑，就只做terminal内能实现的功能。


## Requirement

因为我没钱买API，（当然，如果我有钱也不需要烦恼这么多了，可以直接去做我想做的事情，过我想过的生活了），所以 24-3h 内的所有Agent实际上调用的是本地部署的模型，最大8B左右，这意味着推理能力有限、推理速度有限、推理容量（上下文）有限。

对于A/推出的Claude Code、OpenAI推出的Codex，因为他们是模型产商推出的Agent工具，要我也会弄一些“多subagent重复读取长上下文”来多卖点API。如果只是多买点API能把项目做好，那也很好，曾经使用Gxx5.1推理，一天烧了300元API，还是在左右脑互博，连框架都没搭出来，曾经使用Dxxxxxxx3.5推理，在遇到难题时，总是尝试“回退”，忽视开发要求，在简单的状态之间反复横跳，遇到一点什么问题就“让我们回退到xxx可以运行的版本”，逃避困难的开发需求，浪费时间，浪费API，而不是尝试解决这个问题，添加调试信息，分析问题出现在哪里，尝试解决问题。而且V4还涨价了，正好只有在低谷期才调用API。

我们需要更高的抽象，更聪明的上下文组织方法，更持久的Agent的自主探索导航。必须要有完整的地图，明确前行方向，而不是左右脑互博，反复横跳
精确上下文管理 -> 不只是要对执行路径建图，对于项目结构也要建图，不必反复阅读代码，总结项目结构、接口，是某种“压缩”方法，完整代码、文档 -> 图节点、与其他节点的关系、调用接口。

### Cache / 压缩

基本对象：一个代码文件/一个抽象模块（一块代码）、一个文件（word、pdf、ppt、md）

基本对象是文件原件，在组织上下文时，最好不要直接引用原件。

压缩表示：项目结构、接口文档、文档总结

压缩是处理后的轻量化字符串，便于LLM推理，与KV Cache不同，这里的缓存内容是human readable的。

### 上下文组织

本地部署LLM上下文在128K附近，只组织和当前任务强相关的上下文

全局资源字典 -> LLM处理判断相关性 -> 加载压缩后的上下文

确保上下文中都是LLM推理所需的信息，避免误导，在有限上下文中保证推理的准确性

文件的组织，可以参考多级文件管理

### 项目自主导航

避免Agent左右脑互博，反复回退。

参考Codex的/goal，设定目标结点

记录当前的状态结点，记录所有探索过的结点状态，以及各结点之间的转移方法

避免重复探索结点，判断下一步状态转移像目标结点靠近的概率，判断当前结点在整体地图中的位置

> 上下文组织和项目自主导航都是通过prompt来完成的，文件的结构、项目的结构，系统提示词，（可能的前几次对话内容，让用户自己选择哪些轮次的对话需要保留，也可以让用户指定上下文内容）

### 最小验证原则

从简单到复杂，从模拟到真实，“冒烟测试”

在具体实现前，请确保已经建立数学模型，经过初步模拟验算

以及其他的科研原则，参考[科研注意事项](research-experience/5.6-Sol-research.md)和[科研错题本](research-experience/5.6-Sol-detour.md)，这些要放到system prompt上。

### 经验保存

PPT制作，用户个人的偏好，格式，保存形式也是文件，和其他文件一样，保存、压缩、Cache

### 环境隔离
在Docker中配置环境、执行任务，保证可复现性，同时避免污染宿主环境
