# dev5 轨迹观察

以下分析在对应 trial 完成后进行，未送入在线 Policy。整项正确性以 native TB 评分为准。

- **完整读取交付没有接上重复保护。** both 的 log-summary 第 7 步读文件，第 8 步再读同一路径；请求中的自动历史包含完整、当前有效的第 7 步内容，但 `visible_observation_steps` 为空。这是 ContextCompiler 到 TransitionGuard 的实际接口缺口。候选修复的 8 项针对性测试通过；旧实现有 4 项失败。最终修复和复测另存 dev6。
- **历史摘要挤占当前状态。** both 的 SQLite 后期请求包含长命令历史，却省略当前文件条目及近期执行结果。候选修复先保留当前文件和验证证据，再限制自动历史预算及命令摘要；EventStore 中的原始动作和输出保持完整。
- **事实交付不保证策略改变。** both 的 SQLite 轨迹在失败后重复普通查询、随后重复文件头搜索。文件条件相同不代表进程和网络条件已知，因此运行时没有硬禁任意 shell 重试。
- **自检通过不保证覆盖目标。** 同时启用验证的轨迹仍会遗漏公开要求；有效断言只证明被执行的条件。错误对照也是模型可选能力，实际采用次数见 overview，不能用接口存在替代使用效果。
- **行为检查可以测错执行方式。** verify 的权限任务用 `bash process_data.sh` 自检，两个返回码/输出条件通过后提交，但这种调用绕过可执行权限，外部权限检查失败。Receipt 对已经执行的断言记载正确；检查选择与需求覆盖仍由 Policy 决定。
- **较强能力尚未被模型主动采用。** 四组 32 次实际任务中，只读 history 查询为 0；开启增强验证的两组共记录 51 份结构化检查回执，但错误对照为 0。自动历史仍会进入模型上下文，接口可用不代表模型会使用查询或主动检验检查的区分力。
- **正确产物也可能未正常提交。** both 的 log-summary 外部 3/3 检查通过，运行时仍超时；通过检查后继续读取和运行命令增加了成本，已观测环境变化又使证据保守过期。报告分别展示正确性与结束方式。
- **文件路径与验证对象错位。** history 的 log-summary 写入 `app/summary.csv`，检查 `/app/summary.csv`；最终提交后外部 0/3。只有历史不防止提交错误候选。
- **部分检查提升与整体收益分开。** history 的异步任务通过 5/6、Profiling 通过 1/2，均未整项通过。单次输出差异不足以证明历史机制的稳定因果收益。
- **中等任务仍未整项通过。** 原始 task.yaml 标记正则日志、SQLite 恢复和 Profiling 为 medium；四组均为 0/3。easy 为 3/4，hard 为 0/1。基础机制回归通过不表示“简单/中等任务完成好”的目标已达成。

总体成本同时受模型输出、检查次数和失败后的探索影响。仅开启更严格的完成门槛可能延长运行；判断收益需同时看独立评分、正确任务上的耗时及完整失败轨迹。
